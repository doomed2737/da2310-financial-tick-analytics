Distributed Star Schema & Partitioning Topology

Optimized for zero-shuffle Broadcast Hash Joins and directory pruning on disk

DIMENSION: security_master Broadcast Table
  • 🔑 ticker (PK) : VARCHAR(10)
  • • company_name : VARCHAR(60)
  • • market_cap_category : VARCHAR(15) [Large/Mid/Small]
  • • sector : VARCHAR(30)
⬇️ 1:N Broadcast Hash Join (Broadcasted to Worker JVMs) ⬇️
FACT: market_ticks_fact >2,350,000 Rows
  • 🕒 timestamp (TimeKey) : TIMESTAMP_NTZ
  • 🔑 ticker (FK) : VARCHAR(10)
  • • open, high, low, close : DOUBLE
  • • volume : DOUBLE / BIGINT
  • • typical_price, volume_price : DOUBLE
  • 📁 Partition Key: /market_cap_category=*/ticker=*/

1. Elimination of Network Shuffle

Standard joins across multi-gigabyte tick tables trigger wide shuffle dependencies. By broadcasting the dimension table to every executor, joins occur entirely in local memory via BroadcastHashJoin.

2. Directory-Level Partition Pruning

Physical partitioning by market_cap_category allows queries focusing on Small Caps to skip reading entire directory trees on disk, eliminating I/O bottlenecks.

3. Native Snappy Columnar Storage

All fact data is archived in Apache Parquet format with Snappy compression, enabling column-level skipping and bit-packed dictionary encoding.
